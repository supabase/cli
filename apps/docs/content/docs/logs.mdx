---
title: Logs
description: Read hosted or retained local logs and load newer results on demand
---

Use `supabase logs` to read local or hosted logs. The command defaults to your local stack.

```sh
supabase logs
supabase logs --remote --service postgres --level error
supabase logs sources --remote
```

Use `--remote` for the linked project, `--remote=<ref>` for another project, or `--remote=<branch>` for a branch of the linked project. Local logs require `SUPABASE_EXPERIMENTAL_STACK=1` or `stack = true` under `[experimental]` in your CLI config. Use `--remote` to read hosted logs.

## Browse logs

An interactive terminal opens a log browser when you omit `--output-format`. Use `--output-format text` for one plain-text read. The browser also stays closed in CI, with `TERM=dumb`, or when stdin or stdout is not a terminal. The first load reads the latest 100 lines from the last hour. Use `--limit` to change the initial line count, up to 1000.

Use the up and down arrows to select a row. Enter opens its full details, and Escape returns to the list. `C` copies the full selected record as indented JSON, including metadata and the original timestamp. `q` exits.

Press `L` to load newer logs through the current time. The browser keeps your selection and viewport. It does not poll in the background. A failed load opens the full error in a scrollable panel. Use the arrows to scroll, Escape to return to the previous list or details, or `L` to retry. The browser preserves your rows, selection, window, and detail scroll. `C` is inactive while the error panel is open.

Hosted filtered refreshes read up to five pages of 1000 rows per load. If more rows remain, the header shows `more pending`. Press `L` to continue toward the same captured end. The next load advances the end once that range is complete. The footer reports the page being loaded. A rate-limited page shows its wait duration and UTC retry time, then retries once after at least 60 seconds, or longer when `Retry-After` requires it. You can quit during the wait.

The header shows the hosted project name and ref, or the selected local stack, plus active filters. If the project name cannot be resolved, it shows the ref. The `Window:` header shows the requested time range, including its captured end. A successful load can extend that end; pending hosted pages keep the same end until the range is complete. For filtered logs, the browser retains up to 1000 rows and approximately 8 MiB, with a visible notice when older rows are discarded. Open details stay pinned to their record. `NO_COLOR` preserves the selection marker without styling.

Copying uses your system clipboard and reports success or failure in the footer. On Linux, install `wl-clipboard`, `xclip`, or `xsel` if no clipboard tool is available.

## Filter logs

```sh
supabase logs --remote --service auth --search "invalid token"
supabase logs --remote --service functions --resource <function-id>
supabase logs --stack feature-a --since start
supabase logs --remote --since 30m --limit 500
```

Repeat `--service` or `--level` to select several values. Hosted `--search` matches a case-insensitive literal substring. Percent and underscore characters have no wildcard meaning.

Use `--since` with a duration or ISO-8601 timestamp. Use `--from` and `--to` for explicit UTC bounds. Do not combine `--since` with `--from` or `--to`. With only `--to`, the range covers the hour ending at that timestamp. Hosted ranges must be at most 24 hours. Local ranges have no 24-hour limit. The lower bound stays fixed when you load newer logs.

Severity comes from service fields, such as Postgres error severity or HTTP status. Unknown severity stays unknown. `--level` requires services with a supported severity mapping. Without `--service`, it searches `postgres`, `edge`, `auth`, `functions`, and `function-edge`. `logs sources --remote --service <service>` lists the supported filters.

## Query hosted logs

Pass SQL with `--sql`, `--file <path>`, or `--file -` for piped stdin. Select a hosted target explicitly:

```sh
supabase logs --remote --sql "select timestamp, id, event_message, log_attributes from logs limit 20"
supabase logs --remote --file errors.sql --since 30m --output-format json
cat errors.sql | supabase logs --remote --file - --output-format stream-json
```

The command reads stdin only with `--file -`. Other invocations leave stdin untouched. `--file -` requires piped input; an empty input or unreadable file fails with a suggestion. `--file` has no `-f` alias.

The query uses ClickHouse SQL over the hosted `logs` table. It does not query Postgres. Select `log_attributes` to keep correlation IDs and user attributes. For example, `where source = 'postgres_logs'` limits rows to Postgres.

The browser keeps all returned SQL rows in their result order. Press `L` to rerun the query over the original lower bound through the current time. A successful query replaces the previous results. The header remains visible even when rows omit timestamps.

Queries use the Management API GET endpoint. Server query limits, retention, and project access apply. A long SQL file may exceed the server URL limit. The CLI reports the HTTP error and does not split or rewrite the query. Local SQL queries are unsupported.

## Read logs in scripts

Without an interactive terminal, `supabase logs` performs one finite read and exits.

```sh
supabase logs --remote --service postgres --level error --output-format text
supabase logs --remote --service postgres --output-format json
supabase logs --remote --service postgres --output-format stream-json
```

Piped filtered text keeps one event per line without hard wrapping and escapes embedded carriage returns and newlines. Progress and retry diagnostics use stderr.

JSON output returns an indented array of full records. Stream JSON emits one compact event per line. Filtered reads emit `log-entry` or `log-marker` events with the full record in `data`. SQL reads emit a `result` event with the array. Local records retain instance IDs, launch IDs, positions, and loss markers. Hosted records retain IDs, severity, attributes, and timestamps. Their `service` uses the selector name, such as `postgres`, while `source` keeps the original value, such as `postgres_logs`.

Use `--output-format text`, `json`, or `stream-json`. The command rejects the legacy `-o/--output` flag.

## Retained local logs

Local reads work while the stack is stopped. They never start a stack or service. `--service postgres` selects the local `database` service. Other selectors include service names, instance IDs, and `gateway` when the stack exposes the shared API listener.

Use `--stack <name>` or `--stack-id <id-or-prefix>` to select an existing stack. `--resource` selects an instance ID and cannot be combined with `--service`. `--since start` reads from each selected service's latest launch.

Local `--level`, `--search`, and `--kind` filters are unsupported. Source discovery lists existing instances and gateway support; it does not promise retained rows exist.

## Compute logs

Compute sources require the experimental Compute feature. Use `--service compute --resource <name>`. `--kind app`, `requests`, and `builds` select the stream. App output has no reliable severity; `--level` requires the request or build kind.

```sh
supabase logs --remote --service compute --resource api --kind requests
```

The deprecated `supabase compute logs` and `supabase stack logs` commands keep their existing flags and follow behavior until removal in v4. They warn on stderr. Their `-f` still means `--follow`; use `--file` for SQL files with `supabase logs`.
