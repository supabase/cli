# `supabase functions deploy [Function name]`

Target: hosted, consent default No — see [Command target](../../../../docs/command-target.md)

## Subprocesses

| Command                                                                                                 | When                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `docker info`                                                                                           | to detect whether explicitly selected local Docker bundling can run                                                                        |
| `docker image inspect <candidate>` (ECR, then GHCR, then Docker Hub)                                    | Docker bundling: check whether the edge-runtime image is already cached locally, tried in registry order, before the network/volume ensure |
| `docker pull <candidate>`                                                                               | Docker bundling, cache miss on a candidate: pull with 2 retries (4s/8s backoff) before falling through to the next registry candidate      |
| `docker run --rm ... --label com.supabase.cli.project=<id> --label com.docker.compose.project=<id> ...` | when Docker bundling is selected/available; labeled so orphaned containers can be associated with the project                              |

Docker bundling may pull or run the configured edge-runtime image and uses the
`supabase_edge_runtime_<project_id>` Deno cache volume (mounted at
`/root/.cache/deno`).

| `SUPABASE_USE_SLIM_IMAGES`           | resolves the Functions bundler image from the slim `ghcr.io/supabase/cli/edge-runtime` build (`true`/`1` enable); `deno_version = 1` and historical `.temp/edge-runtime-version` pins stay on docker.io; a failed GHCR pull falls back to the same tag and digest on `public.ecr.aws/supabase/cli`; ambient shell only, unlike the neighboring registry override | no                                                      |

| `BITBUCKET_CLONE_DIR`                | when defined (including an empty value), skips creating the named Deno-cache volume and omits its bind mount from the bundler `docker run` (Bitbucket's restricted Docker environment rejects both); project values are passed explicitly to Docker setup                                                                                                        | no                                                      |
| `SUPABASE_EDGE_RUNTIME_DENO_VERSION` | overrides `edge_runtime.deno_version` (which bundler image tag to use) when set, from the ambient shell or project dotenv — takes effect even with no `config.toml` on disk                                                                                                                                                                                      | no                                                      |

## Exit Codes

| Code | Condition                                                                                                                                         |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`  | success                                                                                                                                           |
| `1`  | authentication / project-ref resolution                                                                                                           |
| `1`  | API error or unexpected HTTP status                                                                                                               |
| `1`  | build / bundle failure                                                                                                                            |
| `1`  | invalid function slug or flag conflict                                                                                                            |
| `1`  | a function directory has `import_map.json` instead of `deno.json`                                                                                 |
| `1`  | `HostedMutationDeclinedError` — the consent question was declined                                                                                 |
| `1`  | `HostedMutationConsentRequiredError` — no `--yes`/shell `SUPABASE_YES` on a non-interactive or machine-output run; nothing is deployed or deleted |

## Output

### `--output-format text`

Prints progress and success messages as Functions are deployed, bundled, uploaded, or pruned.

### `--output-format json`

Emits one structured success payload with the project ref, deployed function slugs, and dashboard
URL, after `--prune` has finished deleting. A failing prune emits only the error envelope.

### `--output-format stream-json`

Emits the same structured success payload as a streamed JSON event sequence.

The `--output`/`-o` flag does not change deploy output.

## Notes

- **Config value precedence** (ADR 0032): explicit flag > shell env > project `.env*` > config
  (`config.json` over `config.toml`) > default. The whole config is decoded up front, so an
  invalid value, including an unparsable `SUPABASE_*` override, fails the command.
- If no function name is provided, deploys all functions found in `supabase/functions/`.
- **Import map resolution** per function, first match wins: `--import-map`, then
  `functions.<slug>.import_map`, then the function directory's `deno.json`, then `deno.jsonc`.
  A function directory with `import_map.json` and none of those fails the whole deploy before any
  bundling or upload, naming every affected slug and suggesting renaming the file to `deno.json` or
  setting `functions.<slug>.import_map`; an explicitly configured `import_map.json` is accepted.
  A function that resolves nothing else uses `supabase/functions/import_map.json` when it exists.
- API-based deploys anchor uploaded file names and the recorded `entrypoint_path` /
  `import_map_path` / `static_patterns` at the workdir (relative to the working
  directory, forward slashes). Imports outside the workdir but inside
  the nearest git root still upload, with `../`-relative names. The nearest git
  root is the containment boundary for uploaded imports.
- Bundles locally with Docker by default (`--use-docker` defaults to true and is hidden); `--use-api` selects server-side bundling, and a stopped Docker daemon falls back to it after a `WARNING: Docker is not running`.
- Local Docker bundling mounts existing local values declared under an import map's `scopes` read-only, including targets outside the nearest Git root; each such out-of-root mount prints a `WARN` naming the host path. The mounted target itself is bound as declared; imports reached from inside an out-of-root target are not additionally bound. API source uploads retain their existing source-root restrictions.
- `--use-api`, `--use-docker`, and `--legacy-bundle` are mutually exclusive deploy modes.
- Prints the target banner before anything else.
- **Consent:** one question, `Deploy N Function(s)` on the target, asked after planning and
  before the first bundle, upload or delete. The default answer is No. `--prune` adds
  `delete N Function(s) with --prune` to the same question, so a deploy with pruning never asks
  twice. The question lists the Function slugs on stderr.
- The question lists every enabled Function, including ones the upload later finds unchanged;
  a deploy with nothing enabled and nothing to prune does not ask.
- `--prune` deletes deployed Functions that are not present locally, and runs even when every
  local Function is already up to date.
- **Spec-strict import-map key matching:** the functions import scanner (`walkImportPaths`/`substituteImportMapValue`,
  shared with `functions serve` and `start`'s Edge Runtime bring-up) matches import-map keys
  per the import-maps spec Deno/edge-runtime implement — exact match, or prefix match only
  for a `/`-suffixed key — so a bare-key prefix does not match, and upload sets are
  limited to spec-matching keys; an unwalkable target (`ENOTDIR` — a value routed through a
  file) is skipped with a `WARN` instead of aborting the deploy.
