## Supabase CLI v3.3.0 — 2026-11-23

This release is mostly fixes for local stacks, plus a few new flags. The biggest changes are a local gateway that no longer drops connections under parallel load, and `--stack` on every stack-backed command. One breaking change, the removed `--stack-id` on `supabase stack` commands, needs a look if you script against it.

### ⚠️ Breaking changes

- **`--stack-id` removed from `supabase stack` commands** — use `--stack <name or id>` instead. `supabase logs` keeps `--stack-id` as a hidden deprecated alias. (#7679)
- **`SUPABASE_TYPEGEN` and the `PATH` fallback are gone for Swift type generation** — `gen types --lang swift` now builds the generator from supabase-swift source, so the first run takes a few minutes and needs a Swift toolchain. Use `--swift-typegen-source <version|branch|sha|path>` instead. Results are cached per commit, so later runs are fast. (#7608)

### Highlights

- **Local gateway no longer drops connections under load** — parallel test suites that used to get connection resets now run cleanly. The workaround for #7734 should be removed after you upgrade and restart the stack, because the directives now render by default and adding them again makes `nginx -t` fail with duplicates. (#7735, #7748)
- **`--stack` on every stack-backed command** — `db`, `migration`, `inspect`, `storage`, `gen types`, `test db`, `seed buckets` and `functions serve` accept `--stack <name or id>` (or `SUPABASE_STACK`) and target that stack instead of the default one. A selected stack never falls back silently, so a missing or stopped stack fails with its name in the error. (#7679)
- **Swift types from source, pinned to your project** — `--swift-typegen-source` picks the supabase-swift commit. Without it, the CLI reads the pin from the nearest `Package.resolved`. (#7608)

### New features

- **`supabase config convert --to toml`** — turns `config.jsonc` back into `config.toml` and keeps the JSON file as a `.bak` backup. Use `--dry-run` to preview the output and undo command without writing anything. The default `--to json` behaves as before. (#7741)
- **`supabase db schema declarative sync --fail-on-destructive`** — exits non-zero when the sync finds `DROP TABLE`, `DROP COLUMN` and similar changes, before any migration file is written. Useful in CI. Off by default. (#7747)
- **`supabase sso add --dedicated-scope`** — gives the provider its own entity ID, metadata URL and ACS URL. It's create-only, so `sso update` doesn't accept it. (#7665)
- **Markdown in help text** — command descriptions render emphasis, inline code and links in the terminal. Output is uncolored for agents, pipes and CI. Use `--agent no` to restore normal color detection. JSON keeps the source Markdown. (#7652)
- **`@supabase/config/convert`** — a plain, effect-free entry point for the TOML-to-JSONC converter, for tools that don't want to install `effect`. (#7738)

### Improvements

- **Plan-gate denials are clearer** — `functions deploy`, `projects create` and `bootstrap` now show the upgrade hint, put `error.entitlement` in JSON output, and classify the error as `plan_limit`. The text hint no longer says "Upgrade your plan" for gates that a paid add-on or SMTP provider clears. Gotcha: in a multi-function deploy, one plan-gated failure makes the whole run report `plan_limit`, even if another function failed for a different reason. (#7681, #7632)
- **Flag reference matches the CLI** — `logs --limit` now documents its real default of `100`. (#7700)

### Bug fixes

- **`supabase db reset` finishes with the API ready** — the first Data API request after a reset now sees the new schema instead of a 503, a 400 or the old schema. If this step fails, the CLI prints a warning and the reset still succeeds. (#7716)
- **Stack start continues when Docker times out but the container is running** — `supabase start` no longer fails on a `docker start` timeout if the container is already up, and logs a warning instead. (#7655)
- **Clearer error when Postgres runs out of shared memory** — on macOS, about 30 running native stacks hit the system's shared memory limit. `start`, `stack restart`, `db start` and the shadow-database paths now name the running stacks and suggest `supabase stack list`, `stack stop --stack <id>` or `stack prune --dry-run`. (#7737, #7742)
- **Storage helpers recover from a lost container** — a storage operation no longer fails when its helper container disappears mid-run. Setup scripts retry once on a fresh helper. Snapshot programs don't replay and fail with a clear error instead. (#7711)
- **`$schema` accepted in config files** — editors no longer flag `$schema` as an unknown property in `config.json` or `config.jsonc`. (#7667)
