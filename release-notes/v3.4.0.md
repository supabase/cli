## Supabase CLI v3.4.0 — 2026-11-24

This release changes how new projects are set up and fixes several issues: `supabase init` now writes `config.jsonc`, the native stack starts in rootless containers, and SSO commands stop printing misleading upgrade hints. Read the breaking change below if you have tooling that looks for `config.toml`.

### ⚠️ Breaking changes

- **`supabase init` creates `supabase/config.jsonc` instead of `supabase/config.toml`** — existing projects aren't touched, and the CLI and Branching read either format. If you have tools, scripts, or CI that only look for `config.toml`, update them to also check `config.jsonc` and `config.json`. To keep TOML, run `supabase config convert --to toml` after `supabase init`. (#7756)

### Highlights

- **`config.jsonc` on init** — the new file starts with a `$schema` line, so editors get completion and validation right away. It keeps the commented-out options from the old TOML template. `init --force` replaces any existing `config.toml` or `config.json` with the new file. (#7756)
- **Nudge toward the local stack** — `supabase start` on the legacy backend, and `supabase init` without the opt-in, now point you to the experimental local stack (faster, lighter, one project per worktree). The nudge shows at most once every 7 days and only in interactive terminals or when a coding agent runs the CLI. CI and piped runs see nothing. (#7649)

### New features

- **Local stack nudge for legacy users** — after a fresh `supabase start`, you'll see the steps to switch: remove the fixed ports from `supabase/config.toml` and add `stack = true` under `[experimental]`. `supabase init` without the opt-in suggests `SUPABASE_EXPERIMENTAL_STACK=1 supabase init`. The nudge is tracked in `$SUPABASE_HOME/stack-nudge.json`, and failures to read or write that file never fail `start`. The `start` JSON output is unchanged. (#7649)

### Improvements

- **Clearer stack discovery across branches** — after `git init` or a branch switch, `supabase stack status` lists your project's stacks on other branches when it finds none on the current one. `stack start` shows the same list before creating a new stack. Port conflicts now name the stack holding the port and suggest `supabase stack stop --stack <id>`. (#7670)
- **`config.jsonc` is also added to VS Code's trusted schema domains** — if `.vscode/settings.json` already exists, `init` adds the Supabase schema domain so VS Code loads the schema without a warning. It never creates `.vscode/`. (#7756)

### Bug fixes

- **`supabase start --runtime native` works in rootless podman and distrobox** — containers that share the host's `/tmp` no longer fail every start with `/tmp belongs to uid 65534, not the current user`. (#7759)
- **`supabase sso list`, `add`, `update`, and `remove` no longer show an upgrade hint on unrelated errors** — the extra entitlement lookup is gone, so these commands make no extra requests after a 4xx. The hint only appears when the API says a plan is required. (#7707)
- **`supabase sso list` and `sso add` report the real 404 message** — a 404 used to always say "SAML 2.0 support is not enabled", even when the project wasn't found. Now you see the API's actual message. (#7707)
- **`supabase stack start` and `stack status` point to the right stack** — when the old stack is still running on another branch, port conflicts name that stack instead of the wrong one. (#7670)
